# Руководство для ИИ-ассистентов по проекту quran-text-to-video

Этот документ содержит правила для ИИ-ассистентов, работающих над этим проектом. Пожалуйста, придерживайтесь этих правил, чтобы поддерживать качество кода и избегать регрессий.

## Ключевые Принципы

1.  **Следуй стилю кода**: Анализируй существующий код и придерживайся его стиля, архитектуры и соглашений.
2.  **Сначала проверяй, потом действуй**: Не делай предположений о наличии библиотек или функций. Всегда сначала читай код, чтобы понять, как он работает.
3.  **Тестируй свои изменения**: После внесения изменений вручную проверяй функциональность, чтобы убедиться, что всё работает как надо и ничего не сломалось.

## Логика Ключевых Функций

### 1. Отображение субтитров (элемент `#text-display`)

**Файл:** `rQit/player.js`
**Функция:** `updateSubtitles()`

**Поведение:**
Элемент `#text-display` показывает текст из **второго столбца** таблицы. Какой именно текст показывать, зависит от текущего времени видео (`currentTime`) и тайм-кодов в **первом столбце**.

**Правила работы:**
1.  **Начальное состояние (t=0):** В самом начале воспроизведения должен отображаться текст из **первой строки** таблицы.
2.  **Логика тайм-кодов:** Текст из строки `N` "живёт" **до** наступления тайм-кода (`T_N`), который находится в той же строке.
3.  **Смена текста:** Как только `currentTime` становится больше или равно тайм-коду `T_N` из строки `N`, текст на экране должен немедленно смениться на текст из **следующей строки** (`N+1`).
4.  **Конечный результат:**
    - Если `currentTime` находится между тайм-кодами `T_{N-1}` и `T_N`, должен отображаться текст из строки `N`.
    - Если `currentTime` прошло все тайм-коды, текст не отображается (пустая строка).
    - Строки без тайм-кода всё равно участвуют в последовательности. Текст из такой строки будет показан после прохождения предыдущего тайм-кода и будет "жить" до следующего существующего тайм-кода.

### 2. Масштабирование для мобильных устройств

**Файлы:** `rQit/script.js`, `rQit/style.css`

**Поведение:**
Для корректного отображения на мобильных устройствах, весь интерфейс масштабируется до `0.8`. Это реализовано с помощью определения типа устройства через User-Agent.

**Правила работы:**
1.  **Определение устройства:** В `script.js` при загрузке страницы запускается функция `detectMobile()`, которая проверяет `navigator.userAgent`. Если User-Agent соответствует мобильному устройству, на корневой элемент `<html>` добавляется CSS-класс `is-mobile`.
2.  **Применение стилей:** В `style.css` существуют правила, которые применяются только при наличии класса `.is-mobile` у `<html>` и `<body>`.
3.  **Логика CSS:** Правило `body.is-mobile` применяет `transform: scale(0.8)`. Чтобы избежать появления полос прокрутки и некорректных размеров, `width` и `height` для `body` пересчитываются (`125vw` и `calc(var(--vh, 1vh) * 125)`), а для `html` и `body` устанавливается `overflow: hidden`.
4.  **Избегайте Media Queries:** Не используйте `@media` запросы для реализации этого масштабирования, так как они показали себя ненадежными на некоторых устройствах. Вся логика завязана на класс `.is-mobile`.

### 3. Импорт и Экспорт таблицы

**Файл:** `rQit/table.js`
**Функции:** `exportTable()`, `importTable()`

**Поведение:**
Реализована возможность сохранять и загружать состояние всей таблицы в файл.

**Правила работы:**
1.  **Формат:** Для совместимости с программами для работы с таблицами (например, Google Sheets) используется формат **CSV**.
2.  **Экспорт:** Функция `exportTable()` собирает все данные из таблицы (заголовки и ячейки), преобразует их в CSV-строку и инициирует скачивание `.csv` файла. Файл сохраняется в кодировке UTF-8 и содержит BOM (`\uFEFF`) для корректной работы с кириллицей и другими символами в Excel.
3.  **Импорт:** Функция `importTable()` срабатывает при выборе `.csv` файла. Она считывает файл, парсит его и **полностью перезаписывает** текущую таблицу новыми данными. После этого происходит повторная инициализация всех обработчиков событий, чтобы новая таблица была интерактивной.
